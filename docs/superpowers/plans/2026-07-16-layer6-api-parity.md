# Layer 6 — API Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Layer 6 per `docs/superpowers/specs/2026-07-16-layer6-api-parity-design.md` (revision 2): pagination/filter retrofits, CRUD gap-fills (shows, tag rename, product soft delete, guarded discount delete, cross-order refunds, notes read), three bulk endpoints over shared guarded mutation paths, storefront category browse + product filters + public reviews, and hardened OpenAPI enforcement.

**Architecture:** Four explicit product lookups split live UUID/slug reads from named including-deleted integrity/uniqueness reads before soft delete lands; product and variant PATCH use compositional claim → live re-read → validate-full-patch → single-write primitives shared with bulk setters; discount delete serializes against checkout redemption via a folded `revision` column and shared row locks; storefront filters use tenant-scoped batched slug resolution + correlated `EXISTS` semijoins with an exact cross-driver JSON membership helper; public surfaces expose strict allowlists.

**Tech Stack:** commerce only; SQLite harness + committed pgsql-gated lane; house DTO/controller/claim/route patterns.

## Global Constraints

- Repo: commerce only, branch dev, commits at group boundaries, no attribution/trailers, never stage docs/superpowers/** or .superpowers/**.
- FOLD POSTURE: `commerce_discounts.revision` (`integer`, default 0, matching every existing commerce revision claim) folds into migration 005. NO other schema change unless the 007 query-plan test demonstrates an index gap (then fold into 007). The existing 007 shape is already verified: category/tag links have the composite unique plus both single-column indexes; product attributes have `unique(product_uuid, attribute_uuid)` plus `index(product_uuid)`. Dev DBs sync manually.
- Vocabularies: product status EXACTLY `draft|active|archived`, product type EXACTLY `physical|digital|external|grouped` — one shared declaration each (`src/Catalog/ProductStatus.php`, `ProductType.php`) consumed by create, update, list filter, and bulk; unknown values rejected at the boundary, never persisted.
- Live-vs-history split: `ProductRepository` exposes four deliberately named reads: `findLiveByUuid`, `findLiveBySlug`, `findIncludingDeletedByUuid`, and `findIncludingDeletedBySlug`. EVERY interactive admin/storefront/relationship/review-create/cart/catalog-mutation path uses a live lookup. ONLY named history/integrity paths (review rollup reversal and any direct product-row integrity check) may use including-deleted; order snapshots and historical sales/product reports remain snapshot/query based and do not reload the product. Slug create/rename collision checks deliberately use `findIncludingDeletedBySlug`. Stock report and catalog lists exclude tombstones. The ambiguous `findByUuid`/`findBySlug` names are retired after a grep-enumerated migration.
- Product soft delete: claim `catalog_revision` → post-claim `findLiveByUuid` → `ProductRepository::markDeleted(...)`, one transaction. `markDeleted` is one affected-row-checked SQL update using `CURRENT_TIMESTAMP` and `WHERE tenant_uuid = ? AND uuid = ? AND deleted_at IS NULL`; false maps to the same 404. Variants/stock/media rows remain. Tombstone keeps reserving its slug: create/rename uniqueness checks INCLUDE deleted rows → normal slug-in-use 422 (never a raw unique-constraint error). Cart add/reprice/checkout returns a controlled unavailable-product 422 for a tombstoned line — `pricedLines()`'s missing-row `continue` must NOT silently drop it. A checkout that already read the product live may finish. Re-delete → 404. No restore.
- Shared guarded mutations are compositional, not sequential wrappers. Product PATCH opens one transaction when a guarded field is present, claims `catalog_revision` once, re-reads live once, validates the ENTIRE patch against that fresh row, then applies one final update; `setProductStatus()` delegates to that internal primitive. Variant PATCH with `price` and/or `shipping_class_uuid` opens one transaction, resolves variant→product, claims the parent once, re-reads live parent+variant, preserves the existing sorted current/proposed shipping-class claim protocol, validates the ENTIRE patch, then applies one final variant update; `setVariantPrice()` delegates to that primitive. A multi-field PATCH must never call a guarded setter and then perform a second plain write, partially commit, or double-claim. Bulk consumes the same internal primitives one item at a time.
- Bulk: caps 100 (422 above), duplicate uuids → 422, status validated against the vocabulary up front (422 whole-request). DTOs use `#[ArrayOf('string')]` for `BulkStatusData::$uuids` and `BulkReviewData::$uuids`, and `#[ArrayOf(BulkPriceItemData::class)]` for `BulkPriceData::$items`; malformed uuid / non-int / negative price / malformed nested item fails the whole request BEFORE any write. Per-item atomicity, input order, response 200 `{applied: [uuid...], failed: [{uuid, reason}]}` with CLOSED reason vocab: product/variant `not_found`; review `not_found|invalid_transition`. Row-locking claims serialize (no optimistic "conflict" reason); unexpected exceptions abort the request with 500, never mislabeled as item failures; no exception text reflected. `commerce:write`. No idempotency keys; replays converge.
- Discount delete: claim revision → post-claim redemption probe → delete, one transaction; redeemed → 409 ("disable via status" hint), row intact. `consumeUsage()` updates the discount row before inserting the redemption, so the shared row lock serializes both orderings (delete-first ⇒ consume affects zero rows ⇒ checkout rolls back; consume-first ⇒ delete observes redemption ⇒ 409). Discount PATCH also claims revision with checked affected rows.
- Pagination retrofit (house offset, `Response::paginated`, clamp `max(1, min(100, ?? 24))`): admin products, tags, attributes, shipping zones, shipping classes, tax rates, discounts, cross-order refunds. NOT: categories (tree), per-zone methods, per-variant downloads, per-order refunds (bounded arrays, documented). Every paginated query: stable UUID tie-break after primary sort; count and row queries share predicates exactly.
- Filters: admin products `status`/`q`/`type`; tags/attributes/classes `q`; discounts `status`/`q` (code); tax rates keep `country`/`class`; refunds `status`/`order`/`from`/`to` on `completed_at` (plain optional half-open `date:Y-m-d` bounds, no cap; pending/failed rows lack `completed_at` and never match a date-bounded request). ALL `q` filters use the shared `Support\LiteralLike::pattern()` helper: lowercase input, escape `!` first and then `%`/`_`, wrap in `%...%`, and query with `LOWER(<allowlisted-column>) LIKE ? ESCAPE '!'`. No ad-hoc interpolation.
- Shows (GET single, `commerce:read`, tenant-scoped, non-revealing 404): categories, tags, attributes (embed values), shipping zones (embed locations + methods), shipping methods, shipping classes, tax rates, discounts, reviews, refunds. NOT: attribute values, media, addons, notes.
- Tag rename: PATCH name only (slug immutable); uses existing `TagRepository::claimRevision()` → post-claim re-read → update in one txn.
- Storefront: NEW config keys `commerce.rate_limits.catalog = [(int) env('COMMERCE_CATALOG_RATE_LIMIT', 120), 60]` (product list/show + category tree + review list) and `commerce.rate_limits.review_submit = [(int) env('COMMERCE_REVIEW_SUBMIT_RATE_LIMIT', 5), 60]` (review POST), both consumed through the existing `$rate()` closure. Category tree payload recursive allowlist EXACTLY `slug,name,description,position,image_url,children` (`image_url` null or `/blobs/{blob_uuid}`; uuid/tenant/raw blob uuid/revision never leave). Product filters: `category` exact slug, `tag` exact slug, `attributes` `attribute-slug:value-slug` comma pairs, AND semantics, max 5 (422 above), unknown slugs match nothing (enumeration-neutral). Resolve category/tag in one lookup each and all attribute/value pairs in one tenant-scoped batch before the product query; then use correlated `EXISTS` semijoins (one per attribute pair), NEVER result-multiplying joins. `JsonStringArrayContainsSql::condition(string $driver, string $trustedColumn, string $value): array{sql:string, bindings:list<mixed>}` validates the trusted identifier and returns exact membership SQL/bindings: sqlite `json_each`, pgsql JSON containment with an encoded one-element array, mysql `JSON_CONTAINS` with an encoded scalar; unknown drivers throw and `red` must NOT match `bred`. Order `created_at DESC, uuid ASC`; count and row queries receive the same resolved filter object.
- Storefront reviews: POST lands `pending` ALWAYS; guest `author_name`+`author_email` required (column-width bounds); `rating` 1..5; `body` required, 10,000-char cap; `user_uuid` stored NULL always in v1 (no optional-auth seam — never trust caller-supplied identity); product must resolve live+active first (draft/tombstoned = same 404 as unknown); 201 body exactly `{status: "pending"}`. GET: same live+active guard, approved only, paginated, `created_at DESC, uuid ASC`, field allowlist rating/body/author_name/created_at.
- OpenAPI enforcement: `HttpDocumentationTest` builds a fresh `Router` manifest instead of relying on the minimal test container or route cache: bind `ApplicationContext::class` to the test context, instantiate `Router($this->contextContainer())`, require the extension `routes.php` with that local `$router`, then inspect `Router::getAllRoutes()`. Filter to commerce HTTP namespace handlers; every `[class, method]` action asserts `#[ApiOperation]` + ≥1 `#[ApiResponse]`; unsupported commerce handler shapes fail explicitly. All new routes/DTOs annotated (`#[FromQuery]` + `#[Rule]`).
- Quality gates per group: `composer test`, `composer phpcs`, `composer run analyze`.
